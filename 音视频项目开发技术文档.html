末端通音视频调度系统全开源重构与跨端建设技术方案

100% 纯内网离线部署 中心级绝对强管控 弱网抗丢包与流量自愈 底层硬件容灾避坑 跨三端同构 (Web + Android + 鸿蒙Next)

一、 项目背景与架构定位

现有“末端通”系统基于商业闭源的好视通（HST RTC SDK）构建[cite: 1]，主要应用于指挥大厅与任务现场调度[cite: 1]。为了满足核心业务的自主可控与专网级强指挥要求，系统需彻底移除外部商业 SDK 依赖[cite: 1]，进行全开源改造与强管控能力升级。

1. 纯物理隔离内网部署

运行环境完全无外网连接，无第三方推送服务（FCM/HMS/APNs），所有流媒体分发、录像、瓦片底图必须本地私有化闭环。

2. 移动端全天候保活唤醒

Android 与华为纯血鸿蒙（Next）移动终端在熄屏和后台常驻运行，调度台发起呼叫能秒级响应并建立音视频连接。

3. 中心绝对指挥控制权

调度员拥有最高管控权限，支持远程强制拉入、强制远程开/关麦、强制远程开/关摄、强制移出与焦点锁定，实现对末端设备的统一指挥。

二、 总体技术栈选型

方案选用业内成熟度高、社区活跃的开源基础组件，构建高并发、低延迟且具备绝对管控力的指挥调度底座：

RTC 媒体服务器 LiveKit Server Go / WebRTC (SFU) 高性能开源流媒体服务器，支持 Simulcast、SVC 带宽自适应与集群化扩展；单机/容器化离线即开即用。
服务端混流录制 LiveKit Egress Docker / Chromium / GStreamer 服务端无头浏览器合流，自动拼接多画面并压制水印，输出 1080P MP4 视频，杜绝客户端作弊。

五、 移动端纯内网后台保活与即时呼叫方案

在专网与专用调度终端环境下，移动端通过预授予系统级权限与常驻机制，实现后台长连接、秒级唤醒及自动执行硬件调度：

1. Android 原生保活与全屏拉起流程

  • 前台服务常驻（Foreground Service）：启动 PersistentCallService，声明 foregroundServiceType="microphone|camera|phoneCall|connectedDevice"，挂载不可滑动清除的常驻通知栏。
  • 权限与白名单预设：配置 REQUEST_IGNORE_BATTERY_OPTIMIZATIONS（电池白名单）与 PARTIAL_WAKE_LOCK 确保 CPU 在熄屏休眠时仍能响应网络指令，同时预先授予系统相机与录音常驻权限。
  • 强拉入会与硬件控制响应：收到 FORCE_JOIN_ROOM、FORCE_OPEN_MIC 或 FORCE_OPEN_CAM 信令时，前台服务无需经过用户交互，直接在底层唤醒 AudioRecord 与 Camera2 驱动，自动连接 LiveKit 并开始推流。

2. 鸿蒙（HarmonyOS Next / ArkTS）原生保活与 NDK 接入

  • 后台长任务（Continuous Task）：使用 @ohos.resourceschedule.backgroundTaskManager 申请长任务。待机状态声明 DATA_TRANSFER（数据传输）维持 WebSocket 长连接；收到入会指令时无缝切换至 VOICE_ROUNDTRIP，确保音视频采集持续运行。
  • 系统级通知与指令执行：普通呼叫调用 @ohos.multimedia.audio 与音频播放振铃；收到强拉指令时，直接在后台通过 AbilityContext 调起通话 UIAbility 并自动入会。
  • WebRTC NDK 媒体层封装：通过 OpenHarmony LLVM 工具链编译 libwebrtc.so，通过 N-API 向上暴露接口；接收到强开指令直接调用 CameraKit 与音频底层流水线建立媒体轨道。

六、 弱网通信保障与多人会议流量治理方案

指挥专网及无线移动边缘网络容易出现弱网丢包与多人流量风暴，系统采用一套完整的传输层 QoS 算法与自适应分发机制：

1. 弱网通信保障机制 (QoS)

TWCC 拥塞控制：毫秒级探测信道实际带宽，动态自适应编码码率。
NACK + FlexFEC 纠错：轻微丢包请求重传，中重度丢包通过前向纠错冗余包在本地算法还原，无需往返等待。
音频绝对优先 (Audio First)：极端拥塞下自动暂停视频流；Opus 开启 In-Band FEC 与静音检测（DTX），50% 丢包率下语音依然清晰可懂。

2. 多人流量暴涨治理 (Traffic Control)

Simulcast 三级大小流：推流端同时输出 High(1080P)/Medium(480P)/Low(180P) 三路子流。
Dynacast 动态上行节流：全房间无人放大某路画面时，SFU 自动下发指令让推流端暂停 High 流编码，节省 60% 上行流量与功耗。
视口感知与按需订阅：调度台仅对可见区域拉取视频流，翻页折叠或最小化窗口自动转为纯音频拉流。

七、 全栈自研开发任务与工作量清单（我们写什么 vs LiveKit 自带什么）

LiveKit 提供了底层的算法引擎（TWCC/NACK/FEC/Simulcast路由），但无法感知前端业务视图与排版。我们团队需要开发的重点是“业务视图状态与 LiveKit 节流 API 的联动逻辑”及“NestJS 信令长连接自愈”：

模块分类 LiveKit 底层已自带能力（无需开发） 我们必须自研编码的部分（开发任务工作量）
推流端适配 WebRTC 视频编解码、音频 3A (AEC/ANS/AGC)、RTP 打包 调用 SDK 发布 Track 时显式配置 simulcast: true、dtx: true 与弱网保清晰度策略。
多人防卡顿联动 SFU 大小流路由分发、Dynacast 动态节流信令下发 1. 活跃发言人画质切换器：监听 ActiveSpeakersChanged，将发言者切 High，其余切 Low；
2. Web 分页订阅控制器：翻页时对不可见人员调用 pub.setSubscribed(false)；
3. 视口监听器：利用 IntersectionObserver 监听窗口遮挡自动停流。
信令与弱网自愈 RTC 媒体通道的 ICE-Restart 重启 1. NestJS WebSocket 网关：管理在线状态树，维护掉线 60s 内的消息缓存队列；
2. 移动端指数退避重连：断网后按 1s/2s/4s 递增重试，并发送 RESUME_SESSION 补发遗漏信令。
会控强管控 SFU 侧物理阻断 Track、剔除连接的底层 API NestJS 封装 RoomServiceClient 执行强控；调度台 UI 界面；端侧后台接收指令自动驱动摄像头麦克风推流。
基础设施配置 Docker 容器运行时 编写 config.yaml 开启 dynacast: true，配置固定内网 IP 并清空外网 STUN 探测地址。

十、 纯内网基础设施与网络规划

针对内网防火墙、端口隔离与离线证书环境，规划如下配置策略：

1. 端口开放与防火墙规划

服务组件 协议类型 规划端口 业务用途说明
Nginx (反向代理) TCP 80 / 443 Web 调度台静态资源托管、SSL 证书卸载、业务 API 代理。
NestJS 信令服务 TCP 3000 (或 443 代理) 统一 WebSocket 长连接信令通信。
LiveKit Server TCP 7880 RTC 媒体信令连接 (HTTP/WebSocket)。
LiveKit Server UDP 50000 - 60000 WebRTC 媒体流数据传输 (RTP/RTCP)。
内网 Coturn 服务 UDP / TCP 3478 跨 VLAN、跨子网专网场景下的内网 STUN/TURN 中继。
MinIO 对象存储 TCP 9000 / 9001 S3 API 访问接口与 MinIO 运维控制台。
TileServer GL TCP 8080 离线矢量/卫星地图瓦片发布服务。

2. 离线 WebRTC 与 HTTPS 证书要求

  • 规避公网 STUN 超时：在 LiveKit Server 配置中明确关闭公网 IP 探测，绑定固定内网 IP（rtc.node_ip），清空所有外网 STUN 探测地址，消除内网下 10~30 秒的无谓超时等待。
  • 内网私有 CA 证书链：浏览器调用 getUserMedia 强制要求 HTTPS/WSS 安全上下文。使用 mkcert 生成内网专用根证书（Root CA）并为内网域名签发证书，通过批量策略导入调度台 PC 及移动端系统受信任证书库中。

十一、 移动端底层硬件陷阱与工程深水区避坑指南

在纯内网移动端原生开发与 AI 辅助落地过程中，必须高度重视以下 5 个维度的硬件与系统底层“暗坑”：

1. 啸叫抑制与音频通讯模式

多台终端近距离同室开启免提会引发强烈啸叫。必须在 Android 原生端强制设置 AudioManager.MODE_IN_COMMUNICATION，强行激活底层硬件 AEC（回声消除）与 NS（降噪），禁止使用普通媒体播放模式。

2. 摄像头硬件独占与防闪退

Camera 是排他性资源。当调度台强开摄像头被占用或系统相机崩溃时，端侧 Native 必须捕获 CameraAccessException，向 NestJS 回传 ERROR_CAMERA_BUSY 并自动降级为纯音频，严禁应用闪退。

3. 状态一致性与防“脑裂”

手机断电或拔网线会导致 NestJS 与 LiveKit 状态脱节。必须在 LiveKit 配置 Webhook 回调，以 SFU 的 participant_left 为最终真实事实来源（Source of Truth），反向校准 NestJS 在线树。

4. 专网跨网段与 MTU 分片

手机 4G/5G 专网与中心调度台跨网段时无法直接 P2P，必须通过内网 Coturn 进行 TURN 中继。针对专网 VPN 的 MTU 压缩，在 LiveKit 中限制 RTP 包长为 1200 字节，防止 DTLS 握手包分片丢弃导致连接卡死。

国产系统 ROM 与 AI 避坑提示：
1. 国产 Android 防杀：引导用户开启“允许后台弹出界面”、“自启动”与“锁屏显示”，否则 Full-Screen Intent 会被系统降级为普通静音通知。
2. 防范鸿蒙 ArkTS 幻觉：提示 AI 时必须严格锁定 HarmonyOS Next (API 11/12+ Stage 模型)，严禁使用已废弃的 FA 模型或 Java API，并将 DevEco Studio 的 .d.ts 类型文件喂给 AI 生成代码。
